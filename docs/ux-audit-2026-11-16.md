# UX audit and implementation — 16 November 2026

This is a dated review. Use the [current user guide](user-guide.md) for navigation and feature behavior.

Data Genie lets individuals and teams explore SQLite/PostgreSQL databases, review SQL changes before applying them, share reports, and scope agent access. The interface is React 19 with Vite and plain JavaScript; the API is Python. This pass preserves the existing colors, APIs, database formats, and confirmation/permission rules.

## Audit scope and priorities

Read the README, frontend conventions, application routing, shared controls and styles before editing. Walked through five flows using a separate local review installation: connect/open/manage databases; switch team and manage people; SQL/results/Structure; create/read/edit reports; account settings and uploads. Also checked the public homepage and narrow navigation. Test fixtures include twenty databases, a long filename, two people and a long report; they are illustrative local data.

| Rank | Observed issue | Change | Impact / risk |
| --- | --- | --- | --- |
| 1 | Database actions clipped inside a recent-databases box; opening management elongated rows. | Manage opens one focused popup. Download, move and exact-name removal share that surface. | High / low |
| 2 | Invitations, people, roles and grants made one long permission sheet. | Separate Database access, Workspace role and Invitations views; select one person/database. Keep unsaved drafts mounted across view changes. | High / medium |
| 3 | Twenty database cards dominated the page. | Two databases per page; search and pagination appear after two. Clamp the page after live removals and reset by workspace/search. | High / low |
| 4 | Thin native selects looked unrelated to adjacent buttons. | Consistent 44px minimum height, padding, theme-aware borders, chevrons, focus and disabled states throughout the site. | High / low |
| 5 | Multiple fixed-height vertical boxes competed with the page; long report text needed nested scrolling. | Content controls page height. Editors grow with text; reports retain one overlay scroll area. SQL help and phone table navigation stay in flow. | High / medium |
| 6 | Drag feedback was a large card; targets lacked clear boundaries. | Tiny file-emoji drag bitmap; bordered eligible sidebar/report destinations and explicit hover/rejection feedback. Remove the permanent move-destination panel. Keep select/button alternatives for touch and keyboard. | Medium / low |
| 7 | People selection was a thin text-only select, with long identities and stale selection edge cases. | Avatar/initials, email, role and selected marker; search and four-person pages. Choosing a person replaces details temporarily instead of layering over them. Recover focus after live page removals. | Medium / medium |
| 8 | Search icon overlapped text; uploads had inconsistent drop and error behavior. | Reserve icon padding, use a shared file-drop hook, reject multiple/empty/oversized database uploads with clear feedback. | Medium / low |

Invitations show three pending items per page. Composing, viewing a one-time code and reviewing pending invitations use one task view at a time. Long identities truncate visually with full text retained in the DOM and title. Removing a person remains in Workspace role, away from routine database grants. A viewer receives a clear explanation instead of database controls; owners cannot edit their own access here.

## Verification

- Frontend production build and whitespace checks pass. The repository has no separate lint or TypeScript check scripts.
- Component tests cover popup focus/escape/background locking, preserved drafts, access restrictions, live member removal, twenty-database search/pagination, emoji bitmap dimensions, upload rejection and growing editors. Final frontend suite: **306 passing tests across 40 files**.
- Browser checks use local fixtures only. Database access fits without internal vertical overflow at 1280×720 and 390×844 (657px content/client height in both checks). On the phone viewport, Workspace role measures 574px and the invitation form 643px, with no internal overflow. Selects measure 44px high. Narrow pages have no horizontal document overflow. Role/invitation views, long filenames, SQL execution, mobile navigation and long report editing are checked separately.
- Earlier backend regression run: 564 tests, 36 skipped, passing; the member-profile change also passed its focused backend checks. These UX changes do not claim a live deployment.

## Remaining checks, ranked

1. Run a native drag-and-drop pass in Chrome, Safari and Firefox. Synthetic handler tests pass, but the automated native drag did not complete a move reliably; do not treat it as verified across browsers.
2. On very short windows, high zoom or when showing a validation/conflict message, a popup may need its accessible overflow fallback. Arbitrarily long reports/results cannot fit one viewport; content remains reachable rather than clipped or reduced to tiny controls.
3. Smoke-test production email/Microsoft configuration and external PostgreSQL exports in their configured environments. This visual pass uses local fixtures, without external credentials or email delivery.

Brand redesign, new dependencies, auth/provider policy changes and schema changes were skipped in this UX pass because they do not solve the observed layout problems. Existing earlier implementation work remains intact.

## Follow-up: restore bottom editors

At the user’s request, SQL and Genie now use a viewport-height query workspace with a bottom sticky composer and requests/results above. This is scoped to those two views; team and account pages keep their document layout. Long drafts have a bounded editor height. Desktop checks place the composer at the viewport bottom; at 390×844 both composers end at 776px, above the mobile navigation at 779px. Production build, all 306 frontend tests, and the full backend suite pass (36 optional checks skipped).
